# Cloudflare R2

The implemented driver. R2 is S3-compatible and has no egress fees, which is why
it is the default choice here.

## 1. Create a bucket

Cloudflare dashboard → **R2 Object Storage** → **Create bucket**.

- Pick a name (e.g. `acme-media`), one bucket per environment
  (`acme-media-staging`, `acme-media-prod`).
- Location: **Automatic** unless you have a specific residency requirement.

## 2. Create an API token

**R2 → Manage R2 API Tokens → Create API Token**.

- Permission: **Object Read & Write**
- Scope it to the specific bucket, not the whole account
- TTL: whatever your rotation policy allows

You get an **Access Key ID** and a **Secret Access Key**, shown once. The
**Account ID** is on the R2 overview page.

## 3. Give the bucket a public URL

R2 buckets have **no public hostname by default**, and `STORAGE_PUBLIC_URL` is
required. Two options:

- **Custom domain** (recommended): bucket → **Settings → Custom Domains → Connect
  Domain**, e.g. `media.example.com`. Cloudflare provisions the certificate.
- **r2.dev subdomain**: bucket → **Settings → Public Development URL → Enable**.
  Rate-limited and not intended for production, but fine for development.

If you only ever serve objects through presigned URLs, point `STORAGE_PUBLIC_URL`
at the custom domain anyway — `publicUrl()` uses it to build return values.

## 4. Configure

```bash
STORAGE_DRIVER=r2
STORAGE_BUCKET=acme-media
STORAGE_REGION=auto
STORAGE_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com
STORAGE_ACCESS_KEY_ID=<access-key-id>
STORAGE_SECRET_ACCESS_KEY=<secret-access-key>
STORAGE_PUBLIC_URL=https://media.example.com
```

`STORAGE_ENDPOINT` is the account endpoint — **do not** append the bucket name; the
SDK adds it.

Then import `StorageModule` where you need it ([README](README.md#turning-it-on)).

## 5. CORS (only for direct browser uploads)

Needed only if a browser PUTs straight to a presigned URL. Bucket → **Settings →
CORS Policy**:

```json
[
  {
    "AllowedOrigins": ["https://app.example.com"],
    "AllowedMethods": ["GET", "PUT"],
    "AllowedHeaders": ["Content-Type"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3600
  }
]
```

## Client configuration

Set in `storage.module.ts`. Three things differ from a stock S3 client:

| Option | Value | Why |
| --- | --- | --- |
| `region` | `'auto'` | R2 has no regions |
| `forcePathStyle` | `true` | R2 does not support virtual-hosted-style addressing |
| `requestChecksumCalculation` | `'WHEN_REQUIRED'` | See below |

Since `@aws-sdk/client-s3` v3.729 the SDK attaches CRC32 integrity headers to every
request by default. **R2 rejects them**, typically as a
`Header 'x-amz-checksum-crc32' with value '...' not implemented` error or an opaque
400. Setting both `requestChecksumCalculation` and `responseChecksumValidation` to
`'WHEN_REQUIRED'` restores the old behaviour and is harmless on real S3.

If you upgrade the SDK and uploads start failing with checksum errors, this is why.

## Troubleshooting

| Symptom | Cause |
| --- | --- |
| `NoSuchBucket` | Bucket name mismatch, or the bucket name was appended to `STORAGE_ENDPOINT` |
| `SignatureDoesNotMatch` | Wrong secret, or `region` is not `auto` |
| Checksum / `not implemented` errors | The SDK checksum default above |
| 401 on public URL | Public access not enabled — no custom domain and no r2.dev URL |
| `AccessDenied` on write | Token is read-only, or scoped to a different bucket |
