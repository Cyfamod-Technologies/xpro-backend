# AWS S3

The API supports AWS S3 through the shared S3 client. Create a private bucket in
the AWS region where the API will use it. Keep Block Public Access enabled and
serve objects through presigned URLs or CloudFront.

## Permissions

Give the API identity access only to its bucket. The provider upload flow needs
`s3:PutObject`, `s3:GetObject`, and `s3:DeleteObject` on `arn:aws:s3:::BUCKET/*`.
Add `s3:ListBucket` on `arn:aws:s3:::BUCKET` only if the application needs to
list objects.

On AWS compute, prefer an attached task or instance role. Otherwise, create an
IAM access key and set both access key variables below. S3 credentials are
optional when the AWS SDK can resolve credentials from its default provider
chain. R2 always requires its access key variables.

## Configure

Set these variables on the API's production service, then restart or redeploy:

```bash
STORAGE_DRIVER=s3
STORAGE_BUCKET=xpro-media
STORAGE_REGION=us-east-1
STORAGE_ENDPOINT=
STORAGE_ACCESS_KEY_ID=<access-key-id>
STORAGE_SECRET_ACCESS_KEY=<secret-access-key>
STORAGE_PUBLIC_URL=https://dxxxxxxxxxxxx.cloudfront.net
```

Use the bucket's actual region. `STORAGE_ENDPOINT` should be unset or empty for
AWS S3; the SDK derives the endpoint. For `STORAGE_PUBLIC_URL`, use the
CloudFront/custom domain that serves objects. If files are only accessed with
presigned URLs, the regional bucket URL can be used as the base:
`https://xpro-media.s3.us-east-1.amazonaws.com`.

The S3 bucket policy must permit the API identity to perform the actions above.
For direct browser PUT uploads, configure bucket CORS to allow the app origin,
the `PUT` method, and the `Content-Type` request header.

## Production error: “Object storage is not configured”

This response means the running API has `STORAGE_DRIVER` unset or set to
`none`. Set `STORAGE_DRIVER=s3` and the required bucket, region, and public URL
in the production service's runtime environment. Add credentials unless the
server has an AWS role, then restart/redeploy the API. The setting in a local
`.env` file has no effect on an already running production server.

If the driver is enabled but its bucket, region, or public URL is missing, the
API fails during startup with the names of the missing variables. AWS access or
signature errors after startup usually indicate a wrong region, missing IAM
permissions, or incorrect credentials.
